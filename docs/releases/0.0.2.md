# MiraclePay v0.0.2 — Release Notes

The "make it real" release: everything v0.0.1 described as a
limit is addressed head-on — runtime persistence, live gateway
calls, production hardening — plus a full plugin system.

## Highlights

- **Postgres persistence at runtime.** All API state (28
  collections: users, merchants, payments, webhooks, plugins…)
  snapshots to and hydrates from Postgres. Restarts no longer
  wipe the platform; in-memory mode remains as the explicit
  no-database fallback. v0.0.1-shaped records hydrate cleanly
  (verified by a dedicated test).
- **Live gateway calls.** bKash tokenized, Stripe Checkout,
  PayPal Orders and Razorpay Orders perform real HTTP in
  sandbox mode by default, behind env credentials. Signed
  Stripe/PayPal webhook receivers and a server-verified bKash
  callback settle payments. No credentials → an honest
  NotConfigured, never a fake success.
- **Plugin system.** Confined JavaScript plugins via
  psychoscript (pinned, MIT) plus an HTTP plugin lane:
  manifest-driven, allowlisted network access, per-plugin
  config + KV, hard runtime limits, admin management UI.
  Pilots: manual bank-transfer gateway, BRAC Bank SMS parser.
  See `docs/plugins.md`.
- **Auth completion.** Password reset + email verification
  (hashed, single-use tokens), session management, admin user
  suspension.
- **Product depth.** Onboarding checklist, team members,
  API-key authentication with scope enforcement, dispute
  evidence files, payout schedules, CSV export, dashboard
  search, gateway test-connection, payment-link analytics,
  receipt PDFs, JS SDK coverage for the new surface.
- **Production hardening.** SMTP STARTTLS, graceful shutdown
  with a final snapshot, fail-fast config validation in
  production, liveness/readiness split, backup/restore drill
  and E2E + load smokes in CI, signed Android release builds
  when keystore secrets are configured.

## Numbers

- 100 waves (51–150) on top of v0.0.1's 50; every wave
  CI-verified at job/step level.
- 118 OpenAPI operations (was 89).
- 714+ Rust tests + 8 JS SDK tests, all green; fmt + clippy
  `-D warnings` gated; RustSec audit clean.
- Full AGPL-3.0 LICENSE at the repo root.

## Honest limits

- Live gateway calls are implemented and unit-tested against
  mocked transports, but have **not** been exercised against
  real provider sandbox accounts (no credentials exist in CI).
- The Android release APK is signed only when the repository
  has keystore secrets configured; the v0.0.2 release assets
  are the CI-built debug APK and the **unsigned** release APK,
  labelled as such.
- Plugin `notification` and `webhook_transformer` kinds load
  and are invocable by admins but are not yet wired into the
  dispatch pipeline.
- Nagad's live verify requires the account-specific
  `NAGAD_API_BASE`; there is no guessed default.
